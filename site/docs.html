Quick start

  1. Get an ESP32-C5 board (the DevKitC-1 is about $15). It's a complete detector on its own.
  2. Open Install in Chrome, Edge or Firefox 151+, pick the board, choose Fresh install, press Connect and install.
  3. Open the console, press CONNECT USB. The setup screen asks what the board is: Standalone for one board, Master if you'll add nodes.
  4. Watch the live list. Surveillance gear is sorted to the top; the radar shows how close it is.

What it detects

Everything below comes from what devices broadcast openly. Matches carry a confidence; strong ones raise an alert (red), weaker ones a notice (amber), the rest just appear in the list.

Surveillance gear

  • ALPR cameras: Flock Safety cameras by their Wi-Fi network names ("Flock-7F68FF"), Bluetooth names and IDs, and Flock's own registered addresses; Flock Raven gunshot sensors by their Bluetooth services. A Wi-Fi chip from a maker Flock also uses only counts as a possible camera when it runs an access point (laptops with the same chip don't).
  • Body cams: Axon / TASER, Motorola Solutions and WatchGuard, Digital Ally, Utility BodyWorn, Zepcam.
  • Trackers: Apple AirTags and Find My tags (alert when separated from their owner), Samsung SmartTags, Tile, Chipolo, Google Find Hub tags.
  • Camera glasses: Ray-Ban and Oakley Meta, Snap Spectacles, Vuzix.
  • Drones: FAA Remote ID over Bluetooth and Wi-Fi, decoded: serial or registration number, aircraft type, position with a map link, height, speed and heading, the pilot's position and how far it is from the drone, and the operator's description. Also DJI DroneID, DJI / Parrot / Skydio radios and drone Wi-Fi hotspots.
  • Card skimmers: the serial Bluetooth modules (HC-05, HC-06, JDY and friends) found inside gas pumps and ATMs.

Attacks and hacker gear

  • Evil twin / Pineapple-style: one radio answering as three or more different network names, as a Wi-Fi Pineapple does to lure phones. Caught whatever address it uses.
  • Wi-Fi beacon spam: a burst of fake networks from one transmitter (Flipper, Marauder, ESP32 spam tools). The banner counts them as they come; the fakes are kept out of the counts and the list.
  • Deauth and disassociation floods: someone knocking devices off their Wi-Fi.
  • Sub-GHz jamming (T-Embed CC1101): a fob or alarm band held loud for seconds, as car-theft jammers do.
  • Bluetooth spam: a burst of fake AirPods / Android / Windows pop-ups from one transmitter.
  • Flipper Zero (when its Bluetooth is on, the default), Wi-Fi Pineapple (by Hak5's address), Pwnagotchi (its "hello" beacons). A device whose radios are silent can't be detected by anything that only listens.

Following and lingering

  • Mobile / Portable: a device that stays with you across places (a tracker after about 3 places, anything else after 5).
  • Stationary: surveillance gear that hangs around for 20 minutes.

Everything else nearby

  • Phones and tablets: by Bluetooth, by Wi-Fi probes (addresses that change are stitched back together), by their traffic while connected to Wi-Fi (private addresses included), by maker (the IEEE registry), and phone hotspots ("Rob's iPhone", "Galaxy S24").
  • Vehicles: Teslas (their phone-key Bluetooth), car makers' Wi-Fi hotspots, car stereos and OBD-II dongles.
  • Routers: security (open, WEP, WPA2, WPA3, Enterprise), Wi-Fi generation and channel width, devices connected and channel load, make and model, how long since it restarted, which devices are talking to it, and a channel chart.
  • Bluetooth details: AirPods and Beats battery levels, Apple activity, iBeacon and Eddystone IDs, Fast Pair, thermometers and BTHome sensors, Windows PCs / Xbox / Surface by type, Matter smart-home gear in setup mode. ASK reads a device's own name, maker, model, firmware and battery.
  • Meshtastic and LoRaWAN (Heltec): node names, positions, battery and packet types from the public channel; LoRaWAN devices by their IDs.
  • Distance: a rough range from signal strength, using the device's own transmit power when it says it.
  • Networks phones look for (opt-in, off by default, never logged).

Browsers

Two things need Web Serial: installing firmware and the console over USB. Chrome, Edge and Firefox 151 or newer work on a desktop (Firefox asks once whether to allow the site, then shows the port picker); Opera and Vivaldi usually do; Brave may need Web Serial enabled in its settings. Safari can't, and neither can phones.

Everything else works anywhere. In particular the console over the master's own Wi-Fi needs no Web Serial: join the network SkySentinel-XXXX from any phone or laptop, in any browser, and the console opens by itself (or go to http://192.168.4.1). So an older browser only matters for the few minutes it takes to flash.

Each page shows a yellow WRONG BROWSER FOR USB bar when it can't reach USB.

Installing firmware

Update keeps the board's settings (role, pairing, categories). Fresh install erases everything: use it the first time, for a board that ran other firmware (Meshtastic, Marauder, Bruce), or to start over.

Close anything else using the port first (serial monitors, PlatformIO, Arduino IDE, the Meshtastic app). If the board won't connect, hold BOOT, press install again and let go when the bar moves.

Building it yourself: pio run -e c5 -t upload (envs c5, v8, heltec, cyd, classic).

The console

  • Over USB: plug the master into a computer, open the console in Chrome, Edge or Firefox 151+, press CONNECT USB.
  • Over Wi-Fi: the master runs its own access point. Join it and the console opens. Set a password in SETTINGS > Wi-Fi.
  • Offline: the console is one HTML file. Save it (or use webui/index.html from the source) and it works with no internet.

NOW is devices heard in the last minute, SESSION is everything since the master started, ALERTS counts alerts since the page connected. Hover over anything for an explanation.

Building a cluster

Nodes only join a master you pair them with, and the link is encrypted with the master's own key.

  1. Flash the node. A fresh node starts out waiting to be paired (blue LED blinking, or a "pair me" screen).
  2. On the master's console: CLUSTER > PAIR A NODE > START PAIRING. Pairing stays open for 2 minutes.
  3. Hold the node within arm's reach of the master. It shows up in the list with a 6-digit code; the node shows the same code (boards without a screen: press BLINK to see which one it is).
  4. If the codes match, press ACCEPT. The node joins within seconds and the master shares out the work.

To move a node to another master: EDIT > FORGET on the old master, or hold the node's BOOT button for 5 seconds.

Long Range link

For a node that's too far from the master (another building, the far end of a property), turn on SETTINGS > Long Range link to nodes. It uses Espressif's LR mode, which reaches several times further or through more walls. At normal distances leave it off: the regular link is faster.

  • Speed: 500 kbit/s (default) or 250 kbit/s for the most reach.
  • Known issue: a bug in Espressif's Wi-Fi driver (esp-idf #19269) occasionally jams the link. The node notices within 1.5 seconds, restarts itself and is back a few seconds later. At 500 kbit/s this happened about once every several hours in testing; at 250 kbit/s every 10 to 45 minutes. With Long Range off it wasn't seen.

Choosing a master

Any board marked "Master" below can run the cluster. Pick it on first start, or later in the console: SETTINGS > ROLE > MASTER (the board reboots into it; no reflash). The master keeps the device list, serves the console over its own Wi-Fi, pairs the nodes and keeps the log. Its own radio still listens, but stays on Wi-Fi channel 6 so it can hear the nodes.

Whatever the master can't hear, a node can: a C5 node adds 5 GHz, a Heltec or Cardputer adds LoRa and GPS, a CYD adds Classic Bluetooth and the touch dashboard, a T-Embed adds sub-GHz.

Board notes

ESP32-C5 DevKitC-1

Use the port labeled USB. The only supported chip with 5 GHz Wi-Fi, so it makes the best master. LED colors: slow blue = waiting to be paired, slow green = pairing open, white flash = identify.

Heltec Wireless Tracker

Adds LoRa 915 MHz (Meshtastic nodes, LoRaWAN trackers) and GPS. With a GPS fix the master stamps every log entry with the time and place. Give it a view of the sky; a cold start takes from 30 seconds to a few minutes. Its card on the master shows GPS 3D · 9 sats when locked.

CYD and ESP32-32E

  • First start: tap the three crosses (a fingernail works best), pick your board, check the colors.
  • Blank or garbled screen: hold BOOT for 3 seconds to switch display chip.
  • SETTINGS > tap the SD line at the bottom: card status and FORMAT.

CYD speaker (alert beeps)

The CYD beeps three times for a red alert: a Find My tag away from its owner, a strong ALPR or body-cam match, following, lingering, a deauth flood, Bluetooth spam. Amber notices stay quiet.

  • Speaker: any small 8 Ω speaker, 0.5 to 2 W, on the board's 2-pin speaker plug (marked SPK or SPEAK). Check the plug size against your board before buying; many listings sell the speaker with the matching lead.
  • Turn it on or off and test it: tap the header for SETTINGS, then Alerts: beep on/off and TEST BEEP. Over USB, the serial command cyd beep does the same.
  • Silent? Run TEST BEEP first. On the ESP32-32E the speaker amplifier is switched on just before each beep, so the first one is never cut off. Still nothing: check the plug is fully seated and the speaker isn't on the battery plug next to it.

CYD GPS (optional)

A GPS on the CYD does what the Heltec's does: it puts the time and place on every log entry and in the GPS window. Any NMEA GPS module works (ATGM336H, NEO-6M, NEO-M8N, BN-220). The CYD only listens to it, so three wires are enough, on the 3-pin expansion plug:

GPS module padCYD 3-pin plug
VCC3.3V
GNDGND
TXD (or TX)IO35
RXDnot connected
  • Follow the labels printed on both boards, not the wire colors: kits use different colors.
  • Not the 4-pin plug. That one is the USB serial port; a GPS there garbles flashing and the console.
  • No setup. The CYD finds the GPS's speed by itself and its header shows GPS -- while searching, GPS 12 (green) once locked. A first fix needs a view of the sky and takes from 30 seconds to a few minutes; indoors it may never lock.
  • GPS window: in the console, click a node's GPS chip on its CLUSTER card: a sky plot of the satellites, signal strength, position (copy, or open on a map), accuracy, altitude, speed, heading and GPS time.
  • Removed it for good? Run gps forget on the CYD so it stops looking.

ESP32-WROOM-32 DevKit

Always a node. Adds Classic Bluetooth inquiry (headphones, HC-05 / HC-06 skimmer radios). Stuck on "Connecting" while flashing: hold BOOT. On Linux with no port: sudo usermod -aG dialout $USER, then log out and in.

Marauder V8

Beta: runs as a C5 master today; its screen and SD card are being added.

LilyGO T-Embed CC1101 (beta)

A sub-GHz node with its own screen. It watches 315, 345, 390, 433.92 and 915 MHz for bursts (key fobs, garage remotes, sensors) and for jamming (a band held loud for seconds, the trick used to keep cars and wireless alarms from hearing their remotes), and raises an alert on the master. Turn the jog wheel for pages: home, the bands (level, noise floor, bursts) and the latest bursts; the back button turns the screen off. Flashing it replaces Bruce. Tire-sensor and fob IDs are next.

Log and SD card

The master logs every surveillance device it finds, following and lingering alerts, floods and Bluetooth spam, with time and place when a GPS node has a fix, plus a track point every minute while moving. Until a GPS clock arrives, the time comes from the computer or phone the console runs on.

  • Master flash: the newest several thousand entries, kept through power cuts. Download: SETTINGS > DETECTION LOG > DOWNLOAD LOG (CSV).
  • SD card: every CYD in the cluster writes the same entries to /SkySentinel/YYYY-MM-DD.csv on a FAT32 card.
  • Get SD files without touching the node: on the master's console, CLUSTER > EDIT > SD CARD > SHOW FILES > DOWNLOAD. The master pulls the file over the cluster link at about 10 to 20 KB a second, re-asking for any piece that goes missing. With the node on USB, SETTINGS > SD CARD does the same over the cable.
  • Format a card: on the CYD (SETTINGS > SD line > FORMAT SD CARD, tap twice), from the master's console (CLUSTER > EDIT > FORMAT SD CARD), or sd format yes. It erases everything on the card.
  • On a map: Google My Maps > Import, choose lat and lon as the position columns.

Alerts

Strong matches (a Flock camera's own network name, an AirTag separated from its owner, Remote ID from a drone) and attacks (an evil twin, Wi-Fi or Bluetooth spam, a deauth flood) raise an alert in the console, on the CYD (with a beep) and in the log. Weaker matches show up in the list without an alert. The banner clears itself after the time you pick; EVENTS keeps every one.

Following and lingering

Set the deployment in SETTINGS: Stationary (home, a parked car), Mobile (driving) or Portable (walking). Mobile and portable watch for a device that keeps showing up across different places; stationary watches for one that hangs around. Mark your own phone, watch and earbuds as mine so they never alert.

Troubleshooting

  • CONNECT USB does nothing: wrong browser (see Browsers), or another program has the port open.
  • Port busy while flashing: close serial monitors and loggers (for example pkill -f "sslog.py /dev/serial").
  • A node keeps dropping: its CLUSTER card shows why it last restarted, its free memory and link losses. Move it closer to the master.
  • No sound from the CYD: SETTINGS > Alerts > TEST BEEP; check the speaker plug and that SETTINGS > Board matches your board.
  • SD error: reseat the card or format it.

Serial commands

Type help in the console's command box for the full list. A few useful ones:

status                 everything about the board, as JSON
devices                table of devices heard in the last minute
cats all | cats none   categories on / off
pair                   open pairing (master) or ask to be paired (node)
node <ID> identify     flash a node's screen or LED
log | log dump | log clear
sd | sd format yes     (CYD)
cyd beep               (CYD) speaker test
